# ReFit 🏃‍♂️💨
> Простое и надежное Android-приложение на Kotlin + Jetpack Compose для управления беговой дорожкой **UNIX FIT R-280** по Bluetooth LE и синхронизации тренировок с **Health Connect** (Google Fit).

---

## 📌 О проекте

Оригинальные приложения, рекомендуемые производителем к дорожке Unix Fit R-280 (FitShow, Kinomap и аналоги), часто работают нестабильно, перегружены рекламой или вовсе не подключаются к тренажеру. Кроме того, старый Google Fit API закрыт, поэтому синхронизация тренировок осуществляется через современный **Health Connect API** (откуда данные автоматически подтягиваются в Google Fit).

**ReFit** построен как монолитная, прозрачная архитектура (все ключевые компоненты собраны в `MainActivity.kt`), что позволяет легко дорабатывать и адаптировать логику прямо в **Antigravity** с помощью модели Flash.

---

## ⚡ Архитектура и стек

- **Язык**: Kotlin
- **UI**: Jetpack Compose + Material 3
- **BLE**: Android Bluetooth Low Energy API (`BluetoothGatt`, `BluetoothLeScanner`)
- **Протокол по умолчанию**: FTMS (Fitness Machine Service, UUID `0x1826`)
- **Синхронизация здоровья**: Health Connect Client API (`ExerciseSessionRecord`, `StepsRecord`, `TotalCaloriesBurnedRecord`)
- **Асинхронность**: Kotlin Coroutines + `StateFlow`

## 🔬 Как устроен протокол и реверс-инжиниринг

Unix Fit R-280 работает на базе BLE-модуля. На практике в таких дорожках встречается один из двух вариантов:

1. **FTMS (Fitness Machine Service)** — международный открытый стандарт (Service UUID: `00001826-0000-1000-8000-00805f9b34fb`).
   - `00002acd-...` — Treadmill Data (телеметрия: скорость, время, дистанция, калории).
   - `00002ad9-...` — Fitness Machine Control Point (запись команд старт/стоп/скорость).
   - `00002902-...` — Дескриптор CCCD для включения уведомлений.

2. **Китайская кастомная шина (FitShow / FFE0 / FFF0)**:
   - Сервисы `0000ffe0-...` или `0000fff0-...`.
   - Обмен короткими hex-пакетами с заголовком: обычно начинается с `0x02`, завершается контрольной суммой XOR и байтом `0x03` (например, запуск мотора: `02 53 01 ... 03`).

## 🚀 План действий в Antigravity (Flash)

китайские контроллеры могут иметь специфичные оффсеты телеметрии. Если при первом подключении данные скорости или дистанции отличаются:

1. **Снимите дамп сервисов**:
   - Запустите приложение на смартфоне.
   - Нажмите **"Scan & Connect BLE"**.
   - Откройте Logcat в Android Studio или в IDE и отфильтруйте по тегу:
     ```text
     BLE_DUMP
     ```
2. **Проверьте UUID**:
   - Если видите `00001826-...` — это чистый FTMS. Потребуется только скорректировать побитовый парсинг пакета `bytes` в методе `parseFtmsTelemetry`.
   - Если `1826` отсутствует, но есть `0000ffe0-...` или `0000fff0-...` — используется протокол FitShow.
3. **Промпт для Flash в Antigravity**:
   > *"Вот UUID сервисов моей дорожки и массив байт, который прилетает в onCharacteristicChanged: `<лог байт>`. Перепиши методы parseFtmsTelemetry и команды управления в моем классе под этот протокол."*

## 📚 Linguistic & Cultural Drop

* **Reverse engineering** — разбор протокола связи закрытого устройства методом перехвата и анализа пакетов данных (сниффинга). Для быстрого анализа без кода рекомендуем утилиту [nRF Connect](https://play.google.com/store/apps/details?id=no.nordicsemi.android.mcp).
* **Boilerplate** — рутинный шаблонный код (обработка пермишенов, регистрация GATT-коллбэков), который сжат в проекте до минимума.
* **Историческая справка**: Беговая дорожка изначально была вовсе не про спорт и фитнес. В 1818 году английский инженер сэр Уильям Каббитт изобрел *treadwheel* (ступальное колесо) как инструмент каторги для британских тюрем. Оскар Уайльд провел два года на таком агрегате в Редингской тюрьме, что вдохновило его на «Балладу Редингской тюрьмы». Поэтому, если Bluetooth на дорожке закапризничает — помните: тренажер буквально создавался для пыток.
* **C'est parti !** [сэ парти́] — французское «Поехали! / Начнем!». Отличный девиз для первого запуска полотна.
